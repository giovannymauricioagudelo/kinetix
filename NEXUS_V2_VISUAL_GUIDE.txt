═══════════════════════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────────────────────┐
│                           Cliente (FastAPI)                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  user_id = 5                                                                │
│  sql = f"SELECT * FROM users WHERE id = {user_id}"                         │
│  # Resultado: SELECT * FROM users WHERE id = 5                             │
│                                                                              │
│  attack_input = "5; DROP TABLE users; --"                                  │
│  sql = f"SELECT * FROM users WHERE id = {attack_input}"                    │
│  # Resultado: SELECT * FROM users WHERE id = 5; DROP TABLE users; --       │
│  # ¡¡¡TABLA ELIMINADA!!!                                                   │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
              ↓ (SQL DIRECTO - CONCATENACIÓN)
┌─────────────────────────────────────────────────────────────────────────────┐
│                       Base de Datos SQL Server                              │
├─────────────────────────────────────────────────────────────────────────────┤
│  Ejecuta: SELECT * FROM users WHERE id = 5; DROP TABLE users; --          │
│  ❌ VULNERABLE - Se ejecuta el DROP                                         │
└─────────────────────────────────────────────────────────────────────────────┘

PROBLEMA: SQL y datos NO están separados. SQL injection es posible.

DESPUÉS (v2.0) - PROCEDIMIENTOS ALMACENADOS ✅
═══════════════════════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────────────────────┐
│                           Cliente (FastAPI)                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  user_id = 5                                                                │
│  execute_procedure(                                                         │
│      "sp_SELECT_users",                                                     │
│      parameters={"user_id": 5}     ← Parámetro separado                   │
│  )                                                                           │
│                                                                              │
│  attack_input = "5; DROP TABLE users; --"                                  │
│  execute_procedure(                                                         │
│      "sp_SELECT_users",                                                     │
│      parameters={"user_id": attack_input}  ← Se trata como DATO            │
│  )                                                                           │
│  # Busca usuario con id = "5; DROP TABLE users; --" (como string)          │
│  # No devuelve nada, pero NO ejecuta el DROP                               │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
              ↓ (PARÁMETRO SEPARADO - NUNCA CONCATENACIÓN)
┌─────────────────────────────────────────────────────────────────────────────┐
│                         Procedimiento Almacenado                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  CREATE PROCEDURE sp_SELECT_users                                           │
│      @user_id INT                  ← Parámetro tipado                      │
│  AS                                                                         │
│  BEGIN                                                                      │
│      SET NOCOUNT ON;                                                       │
│      SELECT * FROM [users] WHERE [user_id] = @user_id;                   │
│  END;                                                                       │
│                                                                              │
│  -- La BD recibe: EXECUTE sp_SELECT_users @user_id = 5                    │
│  -- El parámetro es DATO, nunca SQL                                        │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
              ↓ (EJECUCIÓN SEGURA)
┌─────────────────────────────────────────────────────────────────────────────┐
│                       Base de Datos SQL Server                              │
├─────────────────────────────────────────────────────────────────────────────┤
│  Ejecuta: SELECT * FROM [users] WHERE [user_id] = 5                       │
│  ✅ SEGURO - El DROP nunca se ejecuta                                      │
└─────────────────────────────────────────────────────────────────────────────┘

VENTAJA: SQL y parámetros SIEMPRE separados. SQL injection es imposible.

COMPARACIÓN DE SEGURIDAD - ATAQUES COMUNES
═══════════════════════════════════════════════════════════════════════════════

ATAQUE 1: Classic SQL Injection
────────────────────────────────────────────────────────────────────────────────
  Entrada: "'; DROP TABLE users; --"
  
  v1.0 (SQL Directo):
    SELECT * FROM users WHERE id = ''; DROP TABLE users; --'
    ❌ ¡SE EJECUTA EL DROP! Tabla eliminada.
  
  v2.0 (Procedimiento):
    EXECUTE sp_SELECT_users @id = ''; DROP TABLE users; --'
    ✅ Se trata como parámetro. Busca id = "'; DROP TABLE users; --"
    ✅ Sin resultados, pero tabla segura.

────────────────────────────────────────────────────────────────────────────────
ATAQUE 2: Union-based Injection
────────────────────────────────────────────────────────────────────────────────
  Entrada: "1 UNION SELECT password FROM users--"
  
  v1.0 (SQL Directo):
    SELECT * FROM users WHERE id = 1 UNION SELECT password FROM users--
    ❌ ¡EXTRAE CONTRASEÑAS!
  
  v2.0 (Procedimiento):
    EXECUTE sp_SELECT_users @id = '1 UNION SELECT password FROM users--'
    ✅ Se trata como parámetro. Nada encontrado.

────────────────────────────────────────────────────────────────────────────────
ATAQUE 3: Boolean-based Blind SQL Injection
────────────────────────────────────────────────────────────────────────────────
  Entrada: "1' OR '1'='1"
  
  v1.0 (SQL Directo):
    SELECT * FROM users WHERE id = '1' OR '1'='1'
    ❌ ¡DEVUELVE TODOS LOS USUARIOS!
  
  v2.0 (Procedimiento):
    EXECUTE sp_SELECT_users @id = '1' OR '1'='1'
    ✅ Se trata como parámetro. Nada encontrado (id no existe).

ARQUITECTURA: Los 6 Endpoints
════════════════════════════════════════════════════════════════════════════════

/api/v1/nexus/
├── 1️⃣  POST /create-stored-procedure
│       "Crea SP para tabla"
│       Input:  table_name, operation (SELECT/INSERT/UPDATE/DELETE)
│       Output: SQL CREATE PROCEDURE
│
├── 2️⃣  POST /execute-stored-procedure
│       "Ejecuta SP existente"
│       Input:  procedure_name, parameters
│       Output: rows, columns, data, execution_time
│
├── 3️⃣  POST /crud
│       "CRUD automático (la más simple)"
│       Input:  table, operation, data, id
│       Output: affected_rows, procedure_used
│
├── 4️⃣  GET /stored-procedures
│       "Listar todos los SP"
│       Query:  database=mssql|postgresql
│       Output: List of procedures
│
├── 5️⃣  POST /test-sql-injection
│       "Probar seguridad"
│       Query:  table_name, malicious_input
│       Output: safe=true|false, validation_results
│
└── 6️⃣  GET /procedure-definition
        "Ver definición SQL de SP"
        Query:  procedure_name, database
        Output: SQL definition
