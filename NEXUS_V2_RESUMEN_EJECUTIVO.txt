📊 CAMBIO FUNDAMENTAL
────────────────────────────────────────────────────────────────────────────────

v1.0 (OLD):  SQL Directo           → VULNERABLE a SQL injection
v2.0 (NEW):  Procedimientos        → IMPOSIBLE SQL injection

El código ya NO concatena SQL nunca. Usa parámetros nombrados (@param) en lugar
de concatenar valores directamente.

═══════════════════════════════════════════════════════════════════════════════
🛡️  SEGURIDAD - 4 CAPAS DE VALIDACIÓN
═══════════════════════════════════════════════════════════════════════════════

LAYER 1: Validación de Identificadores
  ✅ Tabla, columnas, nombres de procedimiento
  ✅ Patrón regex: ^[a-zA-Z_][a-zA-Z0-9_]*$
  ✅ Rechaza: comillas, punto y coma, espacios, etc.

LAYER 2: Validación de Tipos de Dato
  ✅ INT → número entero
  ✅ VARCHAR → string < 8000 chars
  ✅ DATETIME → formato ISO
  ✅ BIT → true/false
  ✅ DECIMAL → número decimal

LAYER 3: Detección de Patrones Peligrosos
  ✅ Punto y coma (;)
  ✅ Comentarios SQL (--, /*)
  ✅ Keywords peligrosos (DROP, DELETE, UNION, OR)
  ✅ Comillas simples y dobles

LAYER 4: Parámetros Nombrados en Base de Datos
  ✅ Nunca se concatena en la aplicación
  ✅ La BD trata todo como dato, nunca como SQL
  ✅ Imposible escapar del parámetro

🚀 LOS 6 ENDPOINTS NUEVOS
═══════════════════════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. POST /api/v1/nexus/create-stored-procedure                              │
├─────────────────────────────────────────────────────────────────────────────┤
│ Crea procedimiento almacenado seguro (SELECT, INSERT, UPDATE, DELETE)      │
│                                                                              │
│ Input:  { table_name, operation, columns_types, id_column, database }      │
│ Output: { name, description, parameters, sql_create }                      │
│ Uso:    Crear SP para tabla de usuarios, productos, órdenes, etc.         │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 2. POST /api/v1/nexus/execute-stored-procedure                             │
├─────────────────────────────────────────────────────────────────────────────┤
│ Ejecuta procedimiento con parámetros seguros (parámetros nombrados)        │
│                                                                              │
│ Input:  { procedure_name, parameters, database }                           │
│ Output: { status, rows, columns, data, execution_time_ms, timestamp }      │
│ Uso:    Ejecutar cualquier SP (SELECT, INSERT, UPDATE, DELETE)            │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 3. POST /api/v1/nexus/crud                                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│ CRUD automático: genera SP si no existe, ejecuta, retorna resultado        │
│                                                                              │
│ Input:  { table_name, operation, data, id, database }                      │
│ Output: { status, operation, affected_rows, procedure_name, ... }          │
│ Uso:    INSERT, UPDATE, DELETE sin crear SP manualmente                   │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 4. GET /api/v1/nexus/stored-procedures                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│ Lista todos los procedimientos almacenados disponibles en la BD             │
│                                                                              │
│ Query: ?database=mssql                                                      │
│ Output: { database, total, procedures: [...], timestamp }                   │
│ Uso:    Auditoría, documentación, verificar que SP existe                 │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 5. POST /api/v1/nexus/test-sql-injection                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│ Prueba el sistema contra intentos de SQL injection                         │
│                                                                              │
│ Query: ?table_name=users&malicious_input='; DROP TABLE users; --          │
│ Output: { status, message, safe, validation_results, timestamp }           │
│ Uso:    Testing de seguridad, validación de patrones maliciosos           │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ 6. GET /api/v1/nexus/procedure-definition                                   │
├─────────────────────────────────────────────────────────────────────────────┤
│ Obtiene la definición SQL completa de un procedimiento                     │
│                                                                              │
│ Query: ?procedure_name=sp_SELECT_users&database=mssql                      │
│ Output: { procedure_name, database, definition_query, ... }                │
│ Uso:    Auditoría, documentación, verificar parámetros                    │
└─────────────────────────────────────────────────────────────────────────────┘

═══════════════════════════════════════════════════════════════════════════════
🔐 SEGURIDAD EN COMPARATIVA
═══════════════════════════════════════════════════════════════════════════════

PATRÓN: user_input = "'; DROP TABLE users; --"

❌ SQL Directo v1.0:
   sql = f"SELECT * FROM users WHERE name = '{user_input}'"
   →  SELECT * FROM users WHERE name = ''; DROP TABLE users; --'
   RESULTADO: ¡Se ejecuta el DROP!

✅ Procedimiento v2.0:
   EXECUTE sp_SELECT_users @name = @name
   →  El parámetro se trata como DATO, no como SQL
   RESULTADO: Busca un usuario con nombre "'; DROP TABLE users; --"
